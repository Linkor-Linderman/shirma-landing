# Ширма — лэндинг

Одностраничный сайт десктопного приложения «Ширма»: локально обезличивает Excel клиента, в облачный ИИ уходит только обезличенная копия, ответ возвращается в файл с реальными данными и рабочими формулами.

Стек: Next.js (App Router) и TypeScript. Страницы статические. Заявки принимает серверный route handler.

## Запуск

```bash
npm install
npm run dev
```

Сборка и проверка:

```bash
npm run lint
npm run build
npm test
```

Продакшен-сервер после сборки: `npm start`.

По умолчанию сайт в закрытом режиме: форму можно заполнить, но заявка никуда не уходит.

## Переменные окружения

Скопируйте `.env.example` в `.env.local`. Значения не коммитьте.

| Переменная | Где видна | Зачем |
| --- | --- | --- |
| `LOOPS_API_KEY` | только сервер | Ключ REST API loops.so. Без него заявки не отправляются. |
| `LOOPS_INBOX_EMAIL` | только сервер | Необязательно. Если у ящика работает plus-addressing, Telegram-заявка дополнительно получит адрес вида `name+tg_user@domain`, чтобы контакт было видно в аудитории Loops. Без переменной Telegram сохраняется с `userId`. |
| `SITE_PUBLIC` | сервер, вшивается в страницу при сборке | `true` — обычный `robots.txt` и индексация, форма может отправлять заявки. Любое другое значение или пусто — закрытый режим. **По умолчанию выключено.** |
| `NEXT_PUBLIC_YM_ID` | браузер | Номер счётчика Яндекс Метрики. Пусто — `track()` ничего не отправляет. Вебвизор в коде выключен. |

`LOOPS_API_KEY` не попадает в клиентский бандл: его читают только серверные модули. Не добавляйте к нему префикс `NEXT_PUBLIC_`.

Закрытый режим, пока `SITE_PUBLIC` не `true`:

- `<meta name="robots" content="noindex, nofollow">` (значение берётся на сборке);
- заголовок `X-Robots-Tag: noindex, nofollow` (на каждом запросе);
- `robots.txt` с `Disallow: /`;
- `POST /api/lead` отвечает отказом и не вызывает сервис заявок.

После смены `SITE_PUBLIC` или `LOOPS_API_KEY` проект нужно пересобрать: текст страницы и meta robots фиксируются при `next build`. Route handler смотрит переменные уже во время запроса, поэтому при выключенном флаге заявка не уйдёт даже со старой сборки, где кнопка ещё казалась активной.

## Тексты

Все формулировки лэндинга, согласие у чекбокса и заглушка политики лежат в `lib/content.ts`.

Там же пример таблицы «до/после» — это выдуманный пример, не файл клиента. Фото основателя: `public/founder-placeholder.svg` (или смените `founder.photoSrc`). Контакт в футере: `founder.contactValue` и `founder.contactHref`. Пока ссылка пустая, показывается текст «будет добавлен».

## Заявки и LeadSink

Форма шлёт JSON на `POST /api/lead`. Проверка одна и на клиенте, и на сервере (`lib/lead/validate.ts`): имя, Telegram или email, необязательный ответ, обязательный непредзаполненный чекбокс. Скрытые поля: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `referrer`. От спама: honeypot `hp_website` и лимит 5 запросов за 10 минут с одного IP (в памяти процесса, на нескольких инстансах лимиты независимы).

Если `SITE_PUBLIC` не `true` или нет `LOOPS_API_KEY`, сервер не вызывает внешний сервис и отвечает, что приём заявок выключен. Успех в этом случае не имитируется.

Отправитель — интерфейс `LeadSink` (`lib/lead/types.ts`): метод `send(lead)` с именем, контактом, свободным ответом, `utm_*`, referrer и датой. Сейчас его реализует `LoopsLeadSink` (`lib/lead/loops.ts`): `PUT https://app.loops.so/api/v1/contacts/update`. Контакт создаётся с `subscribed: false`, чтобы Loops не слал рассылки. Свойства контакта sink пытается создать сам: `contact`, `contactMethod`, `message`, `utmSource`, `utmMedium`, `utmCampaign`, `utmContent`, `referrer`, `submittedAt`.

Чтобы перейти на другой сервис, добавьте класс с тем же `send(lead)` и верните его из `getLeadSink()` в `lib/lead/get-sink.ts`. Форму и route handler менять не нужно.

## События

`track(event, props)` в `lib/analytics/track.ts`. Без `NEXT_PUBLIC_YM_ID` это пустая функция. В каждое событие добавляется `utm_source`. Имя, контакт и свободный текст в аналитику не входят.

События: `page_view`, `cta_click`, `form_start`, `form_submit_success`, `scroll_depth` (`how_it_works` и `form`). `form_submit_success` уходит только после реального ответа сервера об успехе.

## Чеклист перед публикацией

- [ ] На `/privacy` вместо заглушки стоит текст политики от юриста. Баннер «Черновик…» убран.
- [ ] Текст согласия у чекбокса заменён (сейчас он помечен как временный в `lib/content.ts`).
- [ ] Есть решение по трансграничной передаче персональных данных: оставить loops.so или подключить другой `LeadSink`.
- [ ] `LOOPS_API_KEY` задан в окружении хостинга, в репозитории его нет.
- [ ] В Loops проверено, что свойства контакта создались и заявка видна (для Telegram — с `userId` или plus-адресом).
- [ ] Блок «Стадия» обновлён, только если к разговорам точно будет демо. Сейчас там «обсудим и покажем макеты».
- [ ] Заменены фото и контакт основателя.
- [ ] `SITE_PUBLIC=true` и проект пересобран. В `robots.txt` больше нет `Disallow: /`.
- [ ] Если нужна Метрика, задан `NEXT_PUBLIC_YM_ID`. Вебвизор не включайте: он может записать поля формы.

## Открытые вопросы

Их решает Linar, не код:

- юридический текст политики и согласия;
- можно ли хранить заявки в loops.so или нужен российский сервис;
- будет ли демо к первым разговорам;
- фото и способ связи основателя;
- срок, за который основатель отвечает на заявку (текст благодарности пока черновой из брифа).
